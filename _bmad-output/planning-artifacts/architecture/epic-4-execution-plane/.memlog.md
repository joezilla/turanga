- (constraint) INHERITED AD-1 control/execution split; Guard broker is the sole path out; sandboxes have no direct network/DB (topological enforcement)
- (constraint) INHERITED AD-2 Guard = one choke point, two policy modules (model→cost/kill via litellm; other→default-deny allowlist+filter hook)
- (constraint) INHERITED AD-3 all-TypeScript first-party; litellm the only non-TS box
- (constraint) INHERITED AD-4 one ephemeral container per Run via Docker API, --runtime=runsc (gVisor) + --network=none, reaped on completion; sandboxes NOT in compose
- (constraint) INHERITED AD-5 Guard two modes: (a) credentialed-connection gateway terminates TLS+attaches held cred; (b) plain allowlisted CONNECT egress; filter hook at both; allowlist=connection destinations+additions, default-deny; agent never holds a raw credential
- (constraint) INHERITED AD-6 LiteLLM is cost-enforcement point: per-agent daily-budget key + per-run key; 429 stops spend regardless of harness; control-api owns cap config, litellm owns spend, others read
- (constraint) INHERITED AD-7 single-writer: control-api owns Agent+Connection; run-orchestrator owns Run; nobody writes spend (litellm owns)
- (constraint) INHERITED AD-8 lifecycle Draft/Active; Run: created→running→(succeeded|failed|killed) mutated only by orchestrator; send-gated → artifact + Run completes
- (constraint) INHERITED AD-9 immutable job spec in (control-api-owned versioned contract); ONE control channel out; harness has no other I/O; runtime ingress = proxy-mediated Connection reads only
- (constraint) INHERITED AD-10 no secret ever in a sandbox: provider keys in litellm, OAuth tokens in egress-guard, both encrypted at rest; sandbox holds only its job spec
- (decision) E4-AD-1 egress transport: sandbox runs --network=none; its ONLY egress is a per-run bind-mounted Unix-domain socket to the egress-guard. At run start the orchestrator registers the run with the guard (guard admin API over the compose network) which provisions the per-run UDS + the run allowlist + the per-run litellm key; orchestrator bind-mounts that UDS into the sandbox; guard tears it down on run end. Binds AC4.1/AD-1/AD-5. Prevents: a network interface on the sandbox / cross-run guard context.
- (decision) E4-AD-2 control channel: job spec injected on stdin (immutable, AD-9); the single control channel is newline-delimited JSON on the container stdout, streamed+validated by the orchestrator against ControlChannelMessageSchema. Guard UDS is egress-only. Prevents: a second control path; conflating egress with the control channel.
- (decision) E4-AD-3 pluggable SandboxRuntime selected by explicit config SANDBOX_RUNTIME: 'gvisor' (--runtime=runsc --network=none) | 'dev-insecure' (plain runc, still --network=none + UDS + stdio, no kernel isolation). dev-insecure refused when NODE_ENV=production. FAIL-CLOSED: if the configured runtime cannot establish a sandbox, the run fails with a stated reason — never a silent downgrade to a weaker runtime (NFR-1/NFR-2).
- (decision) E4-AD-4 run-orchestrator is a module inside control-api (control plane; sole writer of Run state per AD-7) holding the Docker API client. The Docker socket is mounted ONLY into control-api, NEVER into a sandbox. Prevents: a sandbox with the docker socket (=full host escape); a second Run writer.
- (decision) E4-AD-5 per-run LiteLLM key is held by the guard (never the sandbox, AD-10); the guard attaches it when forwarding a model call to litellm. On a 429 the guard signals the orchestrator on the control path, which reaps the sandbox and marks the Run killed within one model round-trip (AD-6/AD-8). Live meter reads spend from litellm.
- (decision) E4-AD-6 Filter Hook is a synchronous interface in the guard: inspect(direction, meta, body?) -> allow | block(reason), invoked at both guard points (credentialed-gateway body + plain-egress connect). A no-op hook is registered by default and must not alter behavior; a sentinel-blocking test hook proves the seam end-to-end (Story 4.6).
- (decision) E4-AD-7 Run state: a runs table owned solely by the orchestrator (control-api DB). control-api exposes an SSE stream that relays a run's control-channel messages to the web test pane; terminal transcript + summed metrics + refusals persist on the Run for later viewing (no spend drift — spend read from litellm).
- (decision) E4-AD-8 run establishment order (fail-closed at each step): 1 orchestrator writes Run=created + snapshots the immutable job spec; 2 mints per-run litellm key under the agent daily-budget key; 3 registers run with guard (allowlist + per-run key + per-run UDS); 4 creates the sandbox container (configured runtime, --network=none, UDS mounted, job spec on stdin); 5 Run=running, streams stdout. Any step failing -> Run=failed with a stated reason; reap + guard teardown always run.
- (assumption) E4 concurrency: MVP is a solo builder; a small max-concurrent-sandbox cap is enforced fail-closed (reject/queue over the cap). Exact number + queueing is a story-level detail.
- (assumption) E4 run wall-clock timeout: the orchestrator reaps a sandbox on done | timeout | kill; the timeout value is a story-level config.
- (direction) E4 story mapping: 4.1 orchestrator+SandboxRuntime+control channel+job-spec (E4-AD-1..4,8); 4.2 test pane SSE stream (E4-AD-7); 4.3 guard allowlist+credentialed gateway over UDS (AD-5, E4-AD-1); 4.4 skill/permission enforcement through the Connection interface (AD-5, inherited); 4.5 cost metering+kill (E4-AD-5, AD-6); 4.6 filter hook seam (E4-AD-6).
- (event) epic-4 load-bearing forks confirmed by user; distilling spine
- (decision) E4-AD-9 harness<->Guard logical-request protocol is a versioned contract (packages/contracts), NOT ad-hoc: a model call is the OpenAI chat-completions shape the Guard proxies to litellm (needed at 4.1); connection reads + plain-egress requests are added in 4.3. Prevents: harness and guard inventing incompatible request shapes over the UDS.
- (decision) E4-AD-10 event provenance (resolves two-sources-of-truth): the harness emits ONLY turns + done on stdout; the Guard reports metrics(cost/tokens) + refusals + 429-kill to the orchestrator over the control-plane path (guard->orchestrator, NOT sandbox I/O, so AD-9's one-channel-out still holds). The orchestrator merges both into the Run + SSE stream. Cost + refusal truth is the Guard/litellm (AD-6), never the harness. Prevents: cost/refusal computed in two places that drift.
- (constraint) SEED: the per-run UDS lives on a shared Docker volume mounted into both egress-guard and each sandbox (both on the same Docker VM) — not a host path — so it crosses the macOS Docker VM boundary. The Guard run-admin API is control-plane-only and authenticated (only the orchestrator calls it).
