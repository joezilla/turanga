- (event) Create/Coaching. Inputs: final PRD (prd-turanga-2026-07-31) + its addendum (architecture-how), brief + competitive-findings, UX spines. Greenfield/solo/single-machine. Deliverable: build substrate only.
- (constraint) Inherited from PRD (binding): FR-7 no un-sandboxed execution ever (fail-closed); FR-8 default-deny egress via allowlist; FR-10 filter-hook seam; FR-11/12 per-run+per-day hard caps w/ live meter + kill-on-breach within one model round-trip; FR-14 Gmail-via-OAuth behind generic Connection; SM-4 zero use-case-specific code in platform paths; NFR-5 single-machine local-first; NFR-6 Warm Ink UI.
- (decision) AD-1 [ADOPTED, user-confirmed] PARADIGM: control-plane / execution-plane split with a mediating Guard broker. Binds: every unit's placement (trusted control plane vs untrusted per-run sandbox). Prevents: security-by-discipline drift — a sandbox with direct network/DB access would let any unit bypass egress/cost controls. Rule: agents run only in ephemeral per-run sandboxes with NO direct network and NO direct DB; the Guard broker is the sole path out. FR-7/8/9/10/12 are enforced topologically.
- (decision) AD-2 GUARD = single choke point, two policy modules. Binds: all sandbox egress routes through one broker. Prevents: a second escape path / two boundaries to prove. Rule: broker classifies each outbound flow — Model Provider destination -> cost meter + kill (FR-12); any other destination -> default-deny allowlist + filter hook (FR-8/10). Cost and allowlist logic are separate modules behind one process.
- (version) Verified current (mid-2026): Next.js 16.2.6 (React 19.2), SvelteKit current, FastAPI 0.138 (not chosen), LiteLLM v1.94.0 MIT (per-key hard budgets, 429 on breach), gVisor/runsc OCI runtime, Firecracker/E2B heavier. Re-verify at build time.
- (decision) AD-3 [user-pref] STACK = all-TypeScript. Binds: control plane, egress-guard proxy, run-orchestrator, and agent harness are TS/Node. Frontend = Next.js OR SvelteKit (user's pick; no ripple into security arch). LiteLLM runs as a language-neutral SIDECAR (model gateway; operated, not authored). Prevents: split-language sprawl. Rule: no Python in first-party code; LiteLLM is the only non-TS runtime box.
- (decision) AD-4 RUNTIME TOPOLOGY: single machine; two tiers. Long-lived services via docker compose = control plane, egress-guard proxy, LiteLLM, Postgres, Redis. Execution plane = ONE ephemeral container PER RUN (not shared, not per-agent), created dynamically by the run-orchestrator via Docker API with --runtime=runsc (gVisor) and --network=none, reaped on completion. Binds: how every Run is isolated + how services deploy. Prevents: shared-runtime state bleed across concurrent runs (FR-7), idle sandbox fleet. Rule: agents never run outside a fresh per-run gVisor container with no direct network/DB.
- (question) OPEN: frontend framework Next.js vs SvelteKit (user to pick; no security-arch impact).
- (decision) AD-5 [user-confirmed] EGRESS GUARD = HTTP(S) forward proxy, the sandbox's only route out. Enforces allowlist by destination host/SNI (no body inspection for MVP); calls the filter hook per request (no-op until a filter registered, FR-10); HOLDS connection credentials and injects them into allowlisted requests so the agent NEVER holds raw OAuth tokens. Allowlist = union of the Agent's attached Connections' declared destinations (default-deny) + optional explicit per-agent additions (NOT purely hand-authored). Binds: how FR-8/9/10 + credential isolation are enforced. Prevents: agent-visible secrets, ad-hoc egress paths.
- (decision) AD-6 [user-confirmed] COST ENFORCEMENT = LiteLLM is the enforcement point (not just meter). Per-agent virtual key carries the daily budget (native LiteLLM, 429-on-breach, Redis-atomic); per-run cap = short-lived per-run key minted under it. On 429 (either cap) the run-orchestrator kills the sandbox container (=kill within one model round-trip). LiteLLM's Postgres/Redis spend record IS the meter the control plane displays (single source, no duplicate accounting). MVP trusts LiteLLM budget enforcement (option a); reserve-then-reconcile hardening (NFR-3) is roadmap given solo/low-concurrency. Binds: FR-11/12 enforcement + who owns spend truth. Prevents: duplicated/ drifting meters.
- (decision) AD-5 AMEND (Hole 1): Guard has TWO egress modes. (a) Credentialed-connection gateway — for an attached Connection (e.g. Gmail), the harness issues a LOGICAL request; the proxy TERMINATES TLS, attaches the held credential, forwards over its own TLS; filter hook runs here. (b) Plain allowlisted egress — CONNECT tunnel, SNI/host allowlist, no creds, opaque body; filter hook at connect-time. Resolves the SNI-vs-credential-injection contradiction. Credential isolation preserved (agent never holds tokens); arbitrary egress stays opaque.
- (decision) AD-6 AMEND (Holes 4+5): Cap CONFIG owner = control plane (user sets caps; pushes them into LiteLLM keys). Spend TRUTH owner = LiteLLM (Postgres/Redis). Different data, one owner each — no drift. Spend cannot be exceeded because LiteLLM 429s the call regardless of harness behavior; the orchestrator 'kill' merely REAPS a run that can no longer progress — it is NOT the cap-enforcement mechanism.
- (decision) AD-7 DATA OWNERSHIP + single-writer. Postgres = database of record, owned by control plane. Entities: Agent (definition+lifecycle state+cost caps), Connection (type+declared destinations; creds in secret store, not the row), Run (transcript, metrics, refusals, status). SINGLE-WRITER: control-plane API is sole writer of Agent/Connection state; run-orchestrator is sole writer of Run state; NOBODY writes spend (LiteLLM owns it, all others read). Binds: one owner per entity. Prevents: two-writer conflicts.
- (decision) AD-8 [user-confirmed, Hole 2] LIFECYCLE. Resting Agent states = Draft, Active (Test is an execution mode, not a resting state). Only transitions: Activate (Draft->Active, gated: model set + per-run & per-day caps set, FR-5) and Deactivate (Active->Draft) — both deliberate control-plane actions. Run lifecycle = created -> running -> (succeeded | failed | killed), mutated only by the orchestrator. Send-gated actions (FR-18) produce an artifact (draft) and the run COMPLETES; approve/send is a separate control-plane action. Mid-run human-in-the-loop 'review' state is ROADMAP (needs run continuation across ephemeral containers).
- (decision) AD-9 INGRESS + contracts (Hole 3). At run start the orchestrator injects an IMMUTABLE job spec (snapshot of agent definition + task input) into the container; the agent cannot mutate its own definition mid-run. Job spec = a first-class VERSIONED contract OWNED BY THE CONTROL PLANE (seed; code owns shape once it exists) so the harness never guesses. Harness emits structured events/results on ONE control channel back to the orchestrator; no other I/O. Runtime data ingress (e.g. email contents) = proxy-mediated Connection reads only (FR-9), never a side channel.
- (decision) AD-10 SECRETS never enter a sandbox. Provider API keys held by LiteLLM; data-connection OAuth tokens held by the egress guard; both encrypted at rest. The sandbox holds ONLY its job spec — no raw credential ever crosses in (reinforces AD-5). Binds: credential custody. Prevents: exfiltration of secrets by a compromised agent.
