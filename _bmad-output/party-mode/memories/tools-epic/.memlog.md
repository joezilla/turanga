- (decision) Two epics, not one — but they share a common denominator: the agent<->tool contract. Remote MCP and containerized MCP are just two ENDPOINT TYPES behind the same contract/broker path.
- (decision) Self-deployed tool containers are TRUSTED (operator-authored via a trusted SDLC). v1 threat model = least-privilege/blast-radius + contract conformance, NOT hostile-code containment.
- (decision) A tool can have its OWN connections; the tool's egress is Guard-intercepted. A tool container is topologically another guard-fronted node (single edge to a guard, own allowlist, no ambient secrets — AD-10 extends to tools). The Guard becomes a BIDIRECTIONAL broker: agent->tool (server side) AND tool->world (client side).
- (decision) Tool calls are OBSERVE-ONLY for now: record invocation statistics (count/latency/outcome/refusal) on the Run; NOT metered against the cost cap, no kill-on-breach. Cost enforcement is a later flag (the E4-AD-10 event ledger already gives the hook).
- (decision) Container-tool lifecycle = long-lived, shared, ONE instance per operator (not per-run). Per-run ephemeral stateful tools deferred.
- (decision) Permission model mirrors Skills: attach a tool to an agent + grant PER OPERATION, Guard-enforced. Discovery via list-tools handshake at attach-time (through the Guard).
- (decision) Contract transport = MCP over streamable HTTP, brokered by the Guard (reuses AD-5a credentialed gateway). Guard becomes bidirectional: agent->tool (server side, Epic 6) + tool->world (client side, Epic 7) — build the halves separately.
- (event) Outcome: two epics captured in epics.md — Epic 6 'Tools: contract + remote MCP' (the spine) and Epic 7 'Self-deployed tool containers' (inherits contract, adds tool plane + packaging contract + tool->world guard). Not story-broken yet; story-break Epic 6 when scheduled.
